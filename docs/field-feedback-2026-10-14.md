# 2026-10-14 実機確認: 管理情報・特性・繁殖・周期負荷の修正仕様

## /www info
- セクション順は現行WWWに合わせ、基本、血統、行動、能力、性格・特性、成長・老化、怪我、関係性能とする。
- 各セクション見出しは先頭データ行に付加し、独立した見出し行は作らない。
- 能力は `基礎値 (実効値) / ランク名 (正規化値)` とし、canonicalを単位変換せずsuffixを付けない。
- 強い特性も実際に強化される場合のみ`II`で表示する。
- 親の遺伝情報を `<名前>(<世代>) <血統ID (=Marker)> <性格> <特性>/<特性>` とする。歴史的Snapshotに無い項目を推定しない。
- 年齢構成・固有情報は現状維持する。
- WWC同様、lang/ja_jp.ymlおよびlang/en_us.ymlを初回起動時に生成し、reloadで不足キーを追記する。既存の翻訳は上書きしない。ユーザー向け文字列をlocale毎に取得する。

## 特性説明
- 通常GUIの特性Loreとクリック後のチャット詳細で、特性名と説明文を表示する。性格のフレーバー説明は表示しない。

## 繁殖個体の初期モード
- Ownerのある繁殖個体は懐き処理と同様に追従モードにし、Ownerを初期指揮者とする。Ownerがない場合は従来の放浪とする。

## 周期負荷
- 全読み込みWWW個体の1秒一括能力再評価を避け、更新を分割し、突発的な同期CPU負荷を抑える。
- 個体初期化、reload、管理コマンド変更、老化/怪我の進行、unload、能力投影を維持する。
- 変更がない値のAttribute書き換えを回避する。
